# 项目规则

## 问题诊断必须基于证据

- 分析 Bug 或异常现象的**根因时，必须先用日志（log）和统计数据（stats）验证假设**，拿到实际运行数据后再定位和修复。
- 禁止"猜测一个原因就直接改代码"的做法。修复前至少要满足以下之一：
  1. 相关代码路径已有**可观测的日志/采样数据**支持该假设；
  2. 临时加入**诊断日志/统计采样**，复现问题后根据数据确认根因。
- 修复完成后，如果诊断日志是临时的，应及时清理（或保留开关但默认关闭）。

## 其他约定

- 调试用的临时开关（如 `DEBUG_XXX`）默认应为 `false`，确认问题解决后关闭。

## Git 提交与推送规则（经用户确认）

### 提交时机：由用户手动触发

- **绝不自动/频繁提交**。每次想提交、或完成一个完整功能点后，我会询问并等待用户明确指示，再由用户决定是否提交。
- 平时的小改动（改参数、调颜色、临时调试）**只在工作区累积**，不主动 `git commit`。

### 提交粒度（当一个功能完成、用户要求提交时）

- 一个完整功能/主题归并为一次提交（如"功耗优化""视觉增强""bug 修复"），**不按每处小改动拆开**。
- 提交信息沿用项目中文风格，建议格式：`<类型>: <做什么>（<补充说明>）`，示例：
  - `功耗优化：DPR降级/鱼群分级/关非核心特性`
  - `visual: 鱼放大+时钟立体化+深度调整`
  - `fix: 时钟数字重叠`

### 分支策略：直接提交主分支

- 当前仅两个长期分支：`master`（桌面 Web 版）、`mobile-showcase`（完整版，含 Android）。
- 日常改动**直接提交到对应主分支**，一般不建临时分分支；仅在做较大的、可能反复推翻的新功能时才考虑 feature 分支。

- 若本地 git 未配置身份，用临时参数提交、**不改全局 config**：

### 推送（GitHub）

- 提交后可攒若干个一起 push，不强制每次 commit 都 push；但完成一个里程碑时应推送一次，避免丢失。
- **本机直连 GitHub 不稳定，推送需走本地代理（Clash `127.0.0.1:7897`）**：
  `git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push ...`
- **代理端口需用户手动开启**（Clash 未启动则 `127.0.0.1:7897` 连不上）。连接失败（如 `Failed to connect ... via 127.0.0.1`）时，**先询问用户是否已开启代理**，再决定：开启后走代理重试，或用户同意的情况下改试直连。

- 推送前若远端有无关内容（如空 README），处理方式由用户确认（必要时 `-f` 强推），不得擅自强制覆盖。

## 文档分工（开发进度 vs 踩坑经验）

- `memory/debug_experience.md`：**踩坑经验 / 根因 / 方法论**（可复用的问题案例）。
- `memory/development_status.md`：**项目进度 / 当前功能状态 / 待办**（"现在做到哪了"）。
- `CHANGELOG.md`：对外可视的**变更记录**（按版本分组）。
- 新增项目管理约定：改动时按内容类型写入对应文档，不混在一处。

## 版本规则（语义化版本）

- 版本号遵循 `主版本.次版本.修订`，维护在 `package.json` 的 `version` 字段。
- 修改判定：
  - **主版本**：重大架构重构 / 不兼容变化（如 WebGPU 渲染重写）。
  - **次版本**：新增完整功能（如惊散系统、新交互）。
  - **修订**：Bug 修复 / 参数调整 / 小优化（默认多数改动落这里）。
- 升版本号时同步在 `CHANGELOG.md` 写对应版本条目；日常小修改先进 `Unreleased` 待发布区，达到门槛后整理成正式版本。

## 【强约束】改动必须构建验证通过

- **改前端代码（src/*.js、index.html、样式等）后，必须以 `npm run build` 构建成功为前提才算完成**，再结束本轮。
- **改 Android 原生层（android/ 下）后**，必须能 `gradlew assembleDebug` 构建成功（若需装机再走 adb 安装）。
- 构建出错时不视为任务完成，先定位修复。
- 后端/无构建项目不适用；但涉及本次改动的资源能否正常打包，需确认无误。

## 实时调试与暂存区分

- `npm run dev`（Vite 热更新）用于**日常调试**，`npm run build` 用于**发版/装机验证**。
- 两者产物不同：dev 不进 dist；build 才产出 `dist/`（供 Capacitor 同步装机）。
